Fetch–execute cycle

Every instruction is fetched from RAM, decoded by the control unit, then executed. Watch the registers and buses light up one micro-step at a time.

Theory Beginner Architecture · CPU ~8 min
The idea

Fetch, then execute

The CPU never “sees” a whole program at once. It repeatedly: fetch the next instruction from memory, decode it, then execute it — using registers as staging posts for addresses and data.

This demo runs a tiny program that loads 10, adds 25, and stores 35 back into RAM.

TipFollow the highlighted box: address path uses PC → MAR; data path uses MDR ↔ RAM.

What each part does

Registers are tiny, named memory cells inside the CPU.

Fetch

PC · MAR · MDR · IR

PC holds the next address. That address goes to MAR, RAM fills MDR, and the instruction is copied into IR.

Control

CU orchestrates

The control unit reads IR, decides the phase (fetch / decode / execute), and steers data between registers and RAM.

Execute

ACC · ALU · RAM

Loads and stores move values through the accumulator. ADD uses the ALU, then writes the result back to ACC (and sometimes RAM).
