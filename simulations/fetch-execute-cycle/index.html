Fetch–execute cycle

Every instruction is fetched from RAM, decoded by the control unit, then executed. Watch the registers and buses light up one micro-step at a time.

Theory Beginner Architecture · CPU ~8 min
The idea

Fetch, then execute

The CPU never “sees” a whole program at once. It repeatedly: fetch the next instruction from memory, decode it, then execute it — using registers as staging posts for addresses and data.

This demo runs a tiny program that loads 10, adds 25, and stores 35 back into RAM.

TipThree buses link CPU and RAM: address (where), data (what), and control (read/write).

What each part does

Registers are tiny, named memory cells inside the CPU.

Address

Address bus · MAR

PC or an operand is copied into MAR, which drives the address bus so RAM knows which cell to use.

Control

Control bus · CU

The CU sends READ or WRITE on the control bus, and steers the fetch / decode / execute phases.

Data

Data bus · MDR · ACC

Values travel the data bus through MDR. Loads fill the accumulator; stores send ACC back into RAM.
